# Frozen-Slow Action Expert: primary-source implementation audit

Audit date: 2026-11-07. This is a static source audit for the proposed dedicated, fully trainable Action Expert positive control. No external repository code was executed; no model weights or datasets were downloaded. Paper claims, inspected code, and proposed adaptations are distinguished below. This audit does not report an Expert training result.

## Qwen-Drive: strongest direct implementation reference

**Cache mapping.** The VLM's full-attention layers are selected from `text_config.layer_types`, and their cached keys and values are extracted directly. The cache contains post-RoPE keys, not the pre-RoPE keys used by this project's snapshot protocol. Expert layer `i` reads cache `i // layers_per_kv`. Defaults are 32 Expert layers and four consecutive layers per cache, giving eight source caches. This is explicitly many Expert layers per source layer, rather than a one-to-one mapping across every VLM layer. See [configuration lines 25–55 and 164–168](https://github.com/QwenLM/Qwen-Drive-1.0/blob/28091c1532e869bc7aee91fc0aef6b3e6fd0b2e0/src/qwen_drive/configuration_qwen_drive.py#L25-L55), [cache extraction lines 166–176](https://github.com/QwenLM/Qwen-Drive-1.0/blob/28091c1532e869bc7aee91fc0aef6b3e6fd0b2e0/src/qwen_drive/modeling_qwen_drive.py#L166-L176), and [actual mapping lines 364–377](https://github.com/QwenLM/Qwen-Drive-1.0/blob/28091c1532e869bc7aee91fc0aef6b3e6fd0b2e0/src/qwen_drive/planning_expert.py#L364-L377).

**Geometry and attention.** The residual width is 1024, whereas query attention width is `16 × 256 = 4096`; there are four KV heads. Expert Q/K receive learned per-head RMS normalization and partial mRoPE. Scene K/V are concatenated directly with Expert K/V, without another scene projection or scene-key normalization. Grouped-query attention reads scene and Expert tokens in one softmax. A learned query-dependent sigmoid gate multiplies the attention result before output projection. SwiGLU and adaptive layer normalization complete the block. The AdaLN residual multipliers are `1 + gate`, so their zero initialization does not suppress the attention/FFN branches. See [layer definitions and GQA lines 162–219](https://github.com/QwenLM/Qwen-Drive-1.0/blob/28091c1532e869bc7aee91fc0aef6b3e6fd0b2e0/src/qwen_drive/planning_expert.py#L162-L219) and [joint attention and gates lines 230–253](https://github.com/QwenLM/Qwen-Drive-1.0/blob/28091c1532e869bc7aee91fc0aef6b3e6fd0b2e0/src/qwen_drive/planning_expert.py#L230-L253).

**Positions and precision.** The VLM prompt's final three-axis position supplies the anchor; Expert positions continue at anchor +1 through +L. The official rotary implementation deliberately reproduces BF16-rounded frequencies and positions fitted by its released checkpoint. That checkpoint compatibility behavior is not a reason to introduce the same rounding into a newly trained Expert using our frozen Slow's native float32 phase computation. The official unpadded attention function has no source-mask argument; a local adaptation must retain the project's explicit valid-token mask. See [prefill/anchor lines 199–211](https://github.com/QwenLM/Qwen-Drive-1.0/blob/28091c1532e869bc7aee91fc0aef6b3e6fd0b2e0/src/qwen_drive/modeling_qwen_drive.py#L199-L211), [rotary precision lines 108–144](https://github.com/QwenLM/Qwen-Drive-1.0/blob/28091c1532e869bc7aee91fc0aef6b3e6fd0b2e0/src/qwen_drive/planning_expert.py#L108-L144), and [waypoint positions lines 305–308](https://github.com/QwenLM/Qwen-Drive-1.0/blob/28091c1532e869bc7aee91fc0aef6b3e6fd0b2e0/src/qwen_drive/planning_expert.py#L305-L308).

**Training evidence reported by the paper.** Stage 2 adapts the shared vision/VLM with perception and VQA; Stage 3 freezes both and trains only the Planning Expert on trajectory supervision, followed by Expert-only RL. Stage 3 uses approximately 2.83 million samples. Its objective is flow matching over 50 waypoints at 10 Hz, not direct eight-pose L1 regression. The explicit 15-epoch schedule belongs to the controlled WOD-E2E ablation, not a verified total budget for the complete main training recipe. Main Stage-3 optimizer-step and batch counts were not established in this audit. See [§§2.1–2.3 and Table 8](https://arxiv.org/html/2609.00111v1).

The release's prefill and sampler are `no_grad`; the Expert's `predict_endpoint` is a separate undecorated computation. This supports the implemented architecture, but static inspection of an inference repository does not verify an executed Expert-only trainer. See [sampling entry point](https://github.com/QwenLM/Qwen-Drive-1.0/blob/28091c1532e869bc7aee91fc0aef6b3e6fd0b2e0/src/qwen_drive/planning_expert.py#L330-L395) and [package description](https://github.com/QwenLM/Qwen-Drive-1.0/blob/28091c1532e869bc7aee91fc0aef6b3e6fd0b2e0/pyproject.toml#L1-L5).

## Think at 5 Hz: different position design, paper-only evidence

The paper reports a fully trained 337M-parameter Expert: 32 layers, residual width 512, one-to-one with frozen LLaMA-7B layers. Rectangular projections produce 32 heads of dimension 128; same-layer source K/V are concatenated with Expert K/V. Expert tokens use learned positions and **no RoPE**; source keys retain their cached rotary phases. The paper does not establish Qwen-style per-head QK normalization or output gates.

Inputs include a state token, four fresh Q-Former visual tokens, and five waypoint queries. The backbone, perception encoder, Q-Former and original heads are frozen. Reported training is five epochs on 27,485 clips, effective batch 32, AdamW with cosine learning rate from `1e-4`, on one 48GB GPU. Staleness is randomized. Open-loop evaluation teacher-forces previous waypoints into the Expert state, a signal the original backbone head lacks; its error advantage therefore does not isolate the cache contribution. These are paper reports, not verified public trainer behavior. See [§§3.1–4.2](https://arxiv.org/html/2607.15621v1).

## AutoMoT: actual separate parameter streams with shared attention

**Code-verified mechanism.** Each decoder layer has original understanding projections/norms/MLP and separate `_mot_gen` action projections/norms/MLP. Tokens use their respective parameter stream, while Q/K/V are assembled into the same attention sequence at the same depth. This is not the Qwen-Drive four-Expert-layers-per-cache scheme. Both streams' Q/K are normalized before the shared native rotary transform. In inference, cache lookup is by the same `self.layer_idx`, and original cache K/V are merged with current action K/V. The inspected action attention projects its output directly; it has no Qwen3.5-style sigmoid query-output gate. See [separate projections lines 392–410](https://github.com/OscarHuangWind/AutoMoT/blob/278fa5ad703f64d2104c163d00b886b4545a6186/Automot/mot/modeling/automot/qwen3vl_navit.py#L392-L410), [normalization/rotary lines 438–491](https://github.com/OscarHuangWind/AutoMoT/blob/278fa5ad703f64d2104c163d00b886b4545a6186/Automot/mot/modeling/automot/qwen3vl_navit.py#L438-L491), [output lines 551–565](https://github.com/OscarHuangWind/AutoMoT/blob/278fa5ad703f64d2104c163d00b886b4545a6186/Automot/mot/modeling/automot/qwen3vl_navit.py#L551-L565), and [per-layer cache merge lines 636–657](https://github.com/OscarHuangWind/AutoMoT/blob/278fa5ad703f64d2104c163d00b886b4545a6186/Automot/mot/modeling/automot/qwen3vl_navit.py#L636-L657).

**Freeze/update behavior.** Trainer defaults include `freeze_vit=True` and `freeze_llm_und=True`. The latter freezes shared embeddings/LM head and original language parameters, then enables `_mot_gen` parameters. Action heads/projectors outside that language submodule remain trainable unless separately frozen. The separate `freeze_und` activation-detach switch defaults false; it must not be confused with the actual parameter-freeze switch. The launcher does not turn all these switches into a single universal setting. See [argument defaults](https://github.com/OscarHuangWind/AutoMoT/blob/278fa5ad703f64d2104c163d00b886b4545a6186/Automot/train/train_automot.py#L398-L425), [freeze implementation](https://github.com/OscarHuangWind/AutoMoT/blob/278fa5ad703f64d2104c163d00b886b4545a6186/Automot/train/train_automot.py#L1000-L1058), and [attention detach switch](https://github.com/OscarHuangWind/AutoMoT/blob/278fa5ad703f64d2104c163d00b886b4545a6186/Automot/mot/modeling/automot/qwen3vl_navit.py#L462-L478).

**Budget evidence.** The current public shell defaults to 30,000 optimizer steps, 1,500 warmup steps and one GPU; the Python defaults supply AdamW, peak LR `1e-4`, cosine minimum `2e-5`, and a packed-token batch. The shell overrides the Python class's 10,000-step default. It loads released AutoMoT weights before optimization, so this is a public continuation recipe, not proof of the original paper's from-scratch budget. See [launcher lines 19–35 and 83–119](https://github.com/OscarHuangWind/AutoMoT/blob/278fa5ad703f64d2104c163d00b886b4545a6186/Automot/scripts/train_automot.sh#L19-L35), [optimizer arguments](https://github.com/OscarHuangWind/AutoMoT/blob/278fa5ad703f64d2104c163d00b886b4545a6186/Automot/train/train_automot.py#L301-L337), [weight loading](https://github.com/OscarHuangWind/AutoMoT/blob/278fa5ad703f64d2104c163d00b886b4545a6186/Automot/train/train_automot.py#L968-L987), and [backward/update](https://github.com/OscarHuangWind/AutoMoT/blob/278fa5ad703f64d2104c163d00b886b4545a6186/Automot/train/train_automot.py#L1233-L1269).

**Paper-reported context.** AutoMoT freezes its Qwen3-VL-4B understanding expert and trains a roughly 1.6B action expert. The action side also receives current RGB/LiDAR-BEV information and predicts decisions, six temporal trajectory points, and 20 route points; it is not a KV-only eight-pose probe. The paper reports eight A100 GPUs and LR `1e-4` to `2e-5`; a complete original update/epoch budget was not established. See [§§3.1–4.1](https://arxiv.org/html/2603.14851v2).

## Explicit adaptation to our six-FA Qwen3.5-2B snapshot

The following are proposed local design choices, not claims that any reference trained this exact model or budget. The local Slow asset configuration has 24 hybrid layers; full-attention source layers are 4, 8, 12, 16, 20 and 24, with two KV heads of dimension 256. Snapshots store normalized **pre-RoPE** K, raw V, original three-axis positions, and a validity mask. The relevant existing contract is [attention.py](../slowfast_v11/attention.py) and [protocol.py](../slowfast_v11/protocol.py).

| Local choice | Required interpretation/check |
| --- | --- |
| Dedicated 24-layer dense Expert, residual width 512, fully trainable | A new model, not truncating or LoRA-adapting the existing full Fast. Fix and report FFN width, parameter count, initialization, normalization, gates and head. Residual width 512 does not force attention width 512. |
| Query heads 8, KV heads 2, head dimension 256 | Gives attention width 2048 with rectangular projections into/out of width 512. Matching source KV geometry avoids scene projection. Query heads must be compatible with two KV heads. |
| Expert layers 1–4 read Slow layer 4; 5–8 read 8; …; 21–24 read 24 | The direct six-source analogue of Qwen-Drive's `cache[i // 4]`. This mapping must be explicit; it is not six caches magically becoming 24 distinct source layers. |
| Restore source RoPE exactly once | Apply the frozen Slow's native partial mRoPE to stored normalized pre-RoPE K using stored source positions. Do not normalize source K a second time, rotate cached post-RoPE K again, or alter V. Own Q/K get their own trainable per-head normalization and the same rotary convention. |
| Continue Expert positions after the valid source prefix | Use each row's last valid three-axis source position, then append Expert positions. Our final source suffix token is a planning query, so the official code's literal “last token is text” rationale does not transfer; verify its actual three-axis positions. This also deliberately differs from the old full Fast's fixed 4096 offset. |
| Frozen Slow, fresh synchronous source every sample | Freeze and evaluate all Slow parameters and construct/detach the source outside its autograd graph. Train the entire Expert. No cross-step mutable cache or native GDN state is needed for this bounded control. |
| Keep the existing eight-pose target and causal ego/command inputs | Deterministic regression and eight learned waypoint queries adapt the references; they do not reproduce Qwen-Drive's flow time/noisy trajectory/history conditioning or AutoMoT's BEV/decision tasks. No teacher-forced previous future trajectory is justified by these references. |
| Preserve padding and intervention semantics | Explicit source validity masks must cover every Expert layer. Fixed/shuffled comparisons must hold recipient metadata and Expert state constant while replacing the intended source K/V. A source-masked inference condition is useful, but without source-masked training it is a diagnostic distribution shift. |

For a comparison with full Fast plus LoRA, keep the same 256 TRAIN rows, held-out log splits, frozen Slow checkpoint, target ordering, supervised examples, update count, effective batch and declared schedule. State explicitly that pretrained initialization, trainable capacity and FLOPs differ. If the Expert receives only state/query tokens while full Fast sees current images directly, that is also a declared input-path difference. Neither reference guarantees success at this small budget. A successful matched-data Expert would establish that this trained readout can exploit this source under its tested conditions; failure would not establish a semantic ceiling of raw KV, and success would not prove every earlier full-Fast limitation was caused by LoRA alone.
