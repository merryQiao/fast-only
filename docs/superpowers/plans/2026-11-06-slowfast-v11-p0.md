# Slow-Fast V1.1 P0/P1 interface implementation plan

> **For agentic workers:** Use superpowers:executing-plans or superpowers:subagent-driven-development, with test-first implementation and independent review.

**Goal:** Deliver a bounded, executable six-layer Slow→Fast KV prototype on the existing NAVSIM four-image, 2 Hz, 8×3 planning interface.

**Architecture:** Add `slowfast_v11/` without modifying the accepted Fast-only source. Capture normalized pre-RoPE Slow keys and raw values; fuse only the eight Fast planning-query rows while preserving native attention for context. Keep differentiable training snapshots distinct from detached inference copies. This iteration establishes interfaces and gradient correctness, not trained KV utility or H1–H4 results.

**Tech Stack:** Existing pinned Qwen3.5 / Transformers / PEFT / PyTorch environment; tiny native 24-layer CPU fixtures; bounded real Qwen3.5-0.8B/2B CUDA audit using existing mini data.

## Fixed contract and boundaries

- Full 24-layer backbones; paired full-attention layers (one based) 4,8,12,16,20,24. Verify head dimensions, KV heads and RoPE contracts, rejecting incompatible models.
- Four chronological CAM_F0 images, original resolution and existing native processor; official NAVSIM four-way command and ego inputs. No new dataset download.
- Fast suffix: ego, command, cache-metadata, eight planning queries. Cache metadata `[age_seconds, dx, dy, sin(dyaw), cos(dyaw), enabled]` uses current-ego-frame source pose, metres/radians/seconds; explicit learned no-cache embedding.
- Slow suffix: ego, command, eight numeric feedback tokens (time,x,y,heading plus explicit missing marker), eight planning queries. Feedback is a completed plan at the same source snapshot, never a future expert trajectory passed as feedback.
- Fixed Fast RoPE offset 4096 on every V1.1 forward, including absent/masked KV. Slow keeps native multimodal positions; reject source positions reaching reserved Fast range. Tiny tests may configure offset 128. This is an interface variant requiring adaptation; it does not promise identity with the original Fast-only checkpoint.
- Preserve native query/key norms, partial mRoPE, GQA, sigmoid query gate and output projection. Native fast attention is computed normally; replace only planning rows immediately before output projection with SDPA over `[Slow KV; Fast KV]`. This deliberately adds computation; measure rather than claim query-count speedups.
- Masked samples retain native output exactly. External invalid columns use an attention mask. Context rows never consume Slow KV. Freeze one snapshot and one gate for all six layers in each call; no native persistent KV/GDN state.
- Inference snapshot copies are detached and own storage; tensors are not inherently read-only. Training snapshots preserve autograd, including device copies. Stage D is single-process model parallel in this prototype, not serialized distributed autograd.
- Admission checks source time ≤ image time and Fast-device ready time ≤ version-selection time, plus episode/navigation/model identity. Offline future-label masks never enter admission.
- Existing official mean L1 trajectory loss remains unchanged. Future prediction, threshold calibration, refresh scheduler, asynchronous publication/transfer, multi-GPU timing and closed-loop benefit experiments are deferred. Do not call a single-GPU audit a multi-GPU validation.
